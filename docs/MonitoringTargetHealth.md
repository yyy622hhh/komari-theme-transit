# 监测目标健康与安全迁移

Transit v1.4.0 在管理员首页工具栏提供“监测目标健康”入口。它只管理北京、上海、广州（广东）三地三网的九个 Komari Ping 任务，不会在升级时自动修改现有目标。

## 状态口径

- **健康**：最近一小时达到采样门槛的节点没有持续失败。
- **单节点路径异常**：只有部分节点的成功率低于 95%。
- **公共目标异常**：同一时间桶至少 5 台、60% 节点同步失败，沿用 Transit 既有公共目标故障口径。
- **证据不足**：任务、在线节点或有效样本不足。

## 验证与迁移

当前目标始终是主目标。每个内置地区/运营商提供同地区运营商 DNS 的 TCP/53 作为备用候选，管理员也可以输入经过格式校验的 IPv4/主机名 ICMP 或 TCP 候选；v1.4.0 不接受 IPv6 候选。

“验证”会创建 `Transit-canary-<地区运营商>-<时间戳>` 临时任务，最多选择原任务中的五台在线节点，30 秒一次。多节点时要求每台至少 3 个样本、总体成功率至少 95%，且不能有节点全部失败；只有一台在线节点时要求 5 次全部成功，并标为低置信度。

管理员再次确认迁移后，Transit 会：

1. 按原名称、客户端、间隔和 `default_on` 创建使用候选目标的新任务；
2. 等待新任务出现首个成功样本；
3. 删除旧任务和本次临时任务。

中途失败会清理本轮创建的资源并保留旧任务。超过 30 分钟的可识别 Transit 临时任务会在下次打开健康中心时自动清理。候选目标只进入 Komari Ping 任务，不会交给回程助手，也不会拼入远程 Shell 命令。

“重建当前任务”执行同样的新 ID 切换，但保持协议与目标不变，适合隔离曾被手工修改目标所污染的历史窗口。

## 助手与插件状态

设置向导显示助手版本、最后成功、最近错误和探测耗时。旧助手缺少这些可选字段时仍可工作，版本不一致只告警、不阻止探测。

伴生插件把不含 token 的 `state-v1.json` 写入 Komari 提供的 `__storageDir__`。写入使用同目录临时文件和原子重命名；损坏文件会改名保留后从空状态启动。任务与批次延续原有 10/20 分钟 TTL，助手状态保留 30 天。
