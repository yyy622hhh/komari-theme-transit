# 监测目标健康与安全迁移（v1.4.1）

管理员首页工具栏的“监测目标健康”管理北京、上海、广州三地三网九个任务。升级不自动改变目标，不接受 IPv6，不修改回程判定及 `transit-route:` 格式。当前目标始终是主目标，DNS/TCP53 仅作为备用候选。

## 当前与历史

- 当前状态：最近三个原始样本全部成功为“正常”，全部失败为“持续失败”，混合为“间歇失败”，不足三个为“证据不足”。最新样本超过 `max(3 × 任务间隔, 3 分钟)` 为“数据过期”，未知间隔按 30 秒。离线来源单独标记，不算目标失败。
- 公共目标当前异常：仅使用近期样本，至少五个持续失败节点且同桶失败占观测节点的 60%；已恢复节点不再由过去的一小时事件认定为当前故障。
- 近一小时：成功率、失败率、同步异常事件和线路评分保留历史原值。恢复显示“已恢复，窗口内曾异常”，不清零历史。TCP 的比例是探测失败率，不是 ICMP 或业务流量的真实丢包率。
- Komari 1.4.3 的精确样本只保留十分钟。当前状态和候选最新证据查询限制在最近约八至九分钟，保留请求余量；一小时历史继续使用原有统计。旧记录接口可能为汇总桶，不能证明连续成功；缺少精确指标时显示未知并停止候选验证。最近成功时间仅表示可读原始窗口内的最后成功，窗口之外未知。
- 首页和拓扑复用共享请求、批量读取及现有刷新调度，不给每张卡增加独立定时器。
- 历史同步异常使用一次逻辑刷新内所有请求分片的观测节点为分母，不按每 50 台的传输批次分别归因；某分片无效时不据此推断公共异常。整体数据延迟以启用地区中最早的有效样本为准，不将无样本地区的零时间计入。
- 波动值是 `P99/P50` 无量纲倍率（例如 `1.00×` 表示 P99 与 P50 相同），不是毫秒抖动；“全部地区”继续按成功样本加权，现有告警阈值不变。

例如一小时窗口内 61 次探测有 2 次失败，失败率仍显示 3.3%；随后最近三个原始样本全部成功时，卡片当前列显示“已恢复”，采样详情显示完整的“正常（已恢复）”。这不是把 3.3% 清零，而是将历史与当前分开。若只有汇总数据或原始样本已过期，不能显示已恢复。

三网卡片将“当前”与“近 1 小时 / 均值 / 失败率”分列，采样格独占整行，不与长状态文字争抢宽度。“采样详情”可展开任务名称、原始样本更新时间和可读窗口内的最近成功；展开只读取共享状态，不新增请求或轮询。拓扑将当前状态置于采样线上方，历史统计在下方，静态基线仍明确标记为配置值。实时历史缺失或过期后使用配置回退值时，显示“备用基线”，只有重新取得有效历史数据才恢复“近 1 小时 / 均值”标签。

## 候选验证

候选只进入 Komari 临时 Ping 任务，不交给助手、不拼入 Shell。验证建立 `Transit-canary-<地区运营商>-<时间戳>`，最多五台原任务在线节点，间隔 30 秒，最多等待四分钟。

原始样本按任务、节点、时间去重排序，排除创建之前的记录。单节点必须最近连续五次成功，失败打断计数，并标为低置信度；多节点每台至少三个样本、总体成功率至少 95%，不能有节点全失败。超时、来源离线、采样不完整或原始接口不可用分别报告。

结果绑定原任务完整快照、候选、临时任务 ID 和三十分钟有效期。迁移前重新读取最新原始样本，不信任已保存的 `migratable`；候选/原任务改变、过期或临时任务被修改必须重新验证。只有明确确认才开始迁移。

## 操作安全与恢复

1. 用 Web Locks 对同一原任务加同源跨标签页锁；不支持时只能查看和验证，不能迁移或重建。此锁不覆盖其他设备，仍需快照复核。
2. 创建替代任务前、删除旧任务前，强制核验管理员权限和原快照（名称、类型、目标、节点、间隔及 `default_on`）；删除前还必须在同一次回查中确认替代任务仍存在且完整快照未变，否则保留原任务并提示重新验证。
3. 创建同配置、新 ID 的任务，等待在线来源产生首个成功样本，再删除旧任务；删除响应丢失时回查。保留原任务的全部节点分配，包括当前离线节点。
4. 任意异常释放忙碌状态并显示原因。旧任务确认仍在时仅清理本次创建且未被别人修改的资源；旧任务删除结果未知或已不存在时保留新任务。清理未确认列出残留 ID，不能声称已回滚。

关闭健康中心仅隐藏界面，操作继续；重开和路由切换共享阶段、进度及等待时间。不承诺关闭浏览器后继续。

本地不含凭据的操作记录保存快照、阶段和新任务 ID。刷新后仅回查后端并展示恢复入口，不自动重建或删除。管理员再次确认后可清理原任务仍存在且未变更的残留资源；旧任务已不存在、资源已被修改或创建响应导致未知 ID 时，需在 Komari 后台按名称与 ID 人工核对，保留有成功样本的替代任务。不要在结果不明时重复创建。

“重建当前任务”只换 ID，不换目标，用于隔离手工改目标遗留的旧窗口。三十分钟以上的 Transit 自有 canary 可在再次打开健康中心时清理；有效操作和锁持有的资源受保护。存在恢复记录时优先只读回查，避免自动清理证据。

拓扑任务的旧任务清理及新任务补偿也要求完整创建快照一致（名称、类型、目标、节点、间隔与 `default_on`）。快照只在确认创建时记录，保存在本标签页 sessionStorage，刷新后可复用；从旧主题配置或其他浏览器取得的 ID 不能补签所有权。任务已改变、缺少快照或回查失败时保留资源，写入流水列出需在 Komari 后台人工核对的 ID。后端没有条件删除接口，因此快照检查仍不能替代跨设备管理员之间的操作协调。

## 插件存储告警

设置向导、全局诊断和脱敏报告独立展示存储“正常/降级/不可用/未报告”。`ok` 只表示接口可用，旧插件不报告存储不等于健康。错误仅显示分类，不包含路径、凭据或原始异常。

写盘失败继续提供探测、保留内存状态和待保存标记，由后续请求按 15、30、60 秒封顶重试；恢复后解除告警。降级时重启可能丢失未保存状态。正常时任务变化立即保存，普通心跳最多每分钟一次。

`state-v1.json` 保持 v1.4.0 格式、0600、同目录原子替换及损坏副本保留。任务/批次 TTL 仍为 10/20 分钟，助手保留三十天。升级保留长期存储，卸载遵循 Komari 删除存储规则。

读取故障恢复时，助手状态按已上报字段合并：普通心跳只更新在线时间和上报版本，不清空磁盘中的最近任务、成功时间、错误或耗时；恢复前收到的新探测结果优先，成功结果可正常清除旧错误。

若读取故障期间又创建了同一节点/城市的任务，恢复时只保留一个活跃任务：优先有效租约，同等条件优先较新的工作；冗余批次对应任务保留失败状态，不再次下发。较新任务已成功时不重新激活旧排队任务。该收敛结果同样落盘，重启后不会重新出现重复租约。

助手任务最多存活十分钟，页面结果等待上限为十分钟加三十秒传输余量，覆盖领取排队、退避、采集和上传；结果一到就写回，不要求等满。旧 Komari 固定远程执行路径仍保持 150 秒。浏览器关闭不保证继续写回。

助手同步采集期间不发送普通轮询。新插件 `/roster` 的可选 `active_job_until` 由现存有效租约推导，向导据此显示“执行中”，不会仅因 40 秒没心跳就提示未安装；完成或租约到期后重新按心跳判断。旧插件缺少字段继续兼容，失联仅提示检查安装或服务状态，不断言未安装。任务十分钟内从未被领取时显示助手未连接，不算线路探测失败。

节点助手安装或升级时，配置先以 0600 临时文件写入，再设置 root/专用用户组与 0640 权限后原子替换；前置写入或权限失败不覆盖旧配置。复制、写入、权限、服务管理任一步失败都返回非零并报告未完成。成功升级会重启助手并核验 active，确保运行的是新脚本；启动失败时新配置可能已就位，需要人工检查服务状态，不宣称已回滚安装。

## 验证与发布

故障测试实际执行存储和 Shell 逻辑，注入文件权限、磁盘空间、重命名、HTTP 状态和 sleep 替身。Linux 隔离实验室矩阵验证 Komari 1.4.2/1.4.3 插件安装、租约、升级、重启、旧格式读取；1.2.5-fix2/1.2.6 验证固定 `admin:exec` 回退，均不接触真实节点。

准备 v1.4.1 不等于发布。提交、推送及生产部署需要授权；授权后先等全部 CI 门禁通过，部署前检查目录属主与可写性并备份旧包和状态，部署后核验版本、轮询、降级状态及重启恢复，不迁移真实监测目标。
